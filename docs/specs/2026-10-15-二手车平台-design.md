## 1. 背景与目标

hmdp 是跟着黑马 Redis 教程做的实战项目，后端已实现：手机号验证码登录、Redis token 滑动续期、
商户缓存三件套、Redis GEO 附近商铺、优惠券秒杀（Lua 原子扣减 + 一人一单 + Stream 异步削峰）、
探店笔记、点赞、关注与 Feed 流、签到。

**本项目要做的事**：用 Vue3 重写前端，把主题从「本地生活点评」改造成「二手车交易平台」，
做出**作品集级、电影级动效**的 PC 端前端。

**为什么是二手车**：`一辆车只能卖给一个人` —— 秒杀 + 一人一单的语义在这里完全自洽，
不需要像卖商品那样硬凑「限量 N 件」。这是所有候选主题里贴合度最高的。

**技术内核不变**：缓存、分布式锁、原子 Lua、异步削峰、LBS、Feed 推拉 —— 原有技术亮点全部保留。

> **`:id` 的语义（2026-10-16，M3 定稿）**：第 5 行 `/seckill/:id` 的 **`:id` 是车 id，不是券 id**。
> 后端只有「按车查券」（`GET /voucher/list/{shopId}`），**没有按券 id 查券的接口** ——
> URL 里放券 id 就只能靠会话把券对象传过来，页面刷不了、也分享不出去。
> 放车 id 则「车 → 该车的秒杀券」这条路可以完整重建。多于一张秒杀券时列出来让用户选。
> 因此第 4 行底部操作条 `StickyBuyBar` 的链接用的是 `voucher.shopId`（= 车 id），
> 而**不是** `voucher.id` —— 两者弄混会打开另一台车的场次，且不会报任何错。

> **第 3 行的「排序」已删（2026-10-16，M3）**：后端 `/shop/of/type` 只认
> `typeId` / `current` / `kind` / `x` / `y`，**没有任何排序参数**。想排只能拿已加载的那 10 条
> 在客户端排，而用户会把结果读成「全站最便宜」—— 在真机分页下那是错的（第 2 页可能有更便宜的）。
> 一个会骗人的控件比没有这个控件更糟，所以价格/里程排序**不做**，只做后端真支持的筛选。

### 不做

- **笔记评论** —— 后端 `BlogCommentsController` 是空壳，功能压根没实现
- UV 统计 —— 只在测试类里跑过，无对外接口
- 支付 / 订单管理 —— hmdp 后端没有对应能力
- **订单列表 / 订单详情**（2026-10-16 M3 明确）—— 后端**没有任何订单查询接口**，
  `VoucherOrderController` 只有 `seckill/{id}` 一个写接口。所以抢购成功后只能展示订单号，
  不能提供「我的订单」入口 —— 那个页面没有任何数据来源。
- **价格 / 里程排序**（2026-10-16 M3 明确）—— 后端无排序参数，理由见 §2 路由表下方的说明
- **后端登出**（2026-10-16 M3 明确）—— `POST /user/logout` 是后端唯一的占位接口
  （返回 `功能未完成`），登出只能前端清 token
- **地图选点** —— 不引地图库，`address` / `area` / `distance` 只作文本展示

## 3. 视觉系统

### 3.1 零彩色 UI（核心约束）

```
色板   纯中性灰阶，不带色相（no blue-tint / no warm-tint）
       #FFFFFF → #0A0A0A

强调   不用色相，用明度反转
       主按钮 = 纯黑底 + 白字
       次级按钮 = 透明底 + 细描边

唯一色彩来源 = 车辆照片本身
       界面零饱和度 → 车漆颜色成为页面上唯一跳出来的东西
```

**状态反馈同样不用颜色**：

- 抢购成功 → 白光从中心爆开
- 抢购失败 → 界面瞬间压暗 + 轻微震动

纯明度语言。不用绿/红。

### 3.2 统一亮色基调（2026-10-15 修订，替代原「混合基调」）

全站统一 `#FFFFFF` 底，不分暗区亮区。

原方案是「营销页暗色做电影感 / 功能区亮色保可用性」。**推翻的理由**：车是抠图资产，
本身没有场景。放在纯黑上时，界面必须补三层空间感（顶光、地平线、暗角）才不让车飘起来，
那三层是界面在替照片演戏；放在白底上，车直接成立，界面可以退到只剩排版。

动效力度仍然分档（见 §6），但那是节奏差异，不再是明暗差异。

| | 旗舰页 | 功能页 |
|---|---|---|
| 页面 | 首页 / 车辆详情 / 抢购页 | 其余 |
| 底色 | `#FFFFFF` | `#FFFFFF` |
| 动效力度 | 电影级 | 精致克制 |
| 内容 | 大图叙事 | 密集信息 |

### 3.3 车是主体

车辆图片永远占据视觉重心，UI 元素退成背景。
列表卡片图占大头，详情页满屏大图，任何装饰不允许抢戏。

### 3.4 字体

- 中文：思源黑体 / Noto Sans CJK（本机字体，不引 webfont）
- 正文与数字：Inter —— 价格、里程、车牌的数字质感是重点
- **展示体：Oswald**（2026-10-15 修订新增）

字体规则：`--font-display` **只用于全大写的拉丁展示文字** ——
AXLE 字标、首屏主标题、首屏车名、品牌 mark、段落 eyebrow。
Oswald 没有 CJK 字形，中文一旦落进来会掉回 Noto，所以混排的中文标题一律不用它。

首屏主标题与车名改用英文，就是为了让这套展示体成立（见 §3.5）。

### 3.5 首屏规格（2026-10-15 修订）

参照物：Minus 给的示例图（`THE MORNING` 那张）—— 全大写、超大字号、紧凑无衬线标题，
配一枚极小、字距拉开的顶部小标签，车居中大图。

| 项 | 规格 |
|---|---|
| 底色 | `#FFFFFF`，底部过渡到 `ink-100` 暗示地面 |
| eyebrow | `AXLE · 严选二手性能车`，11px，`tracking-[0.34em]`，中文 |
| 主标题 | `EVERY CAR DESERVES A SECOND START`，Oswald，`clamp(2.4rem,6.6vw,5.5rem)`，`leading-[0.92]`，大写 |
| 车台 | **尺寸写死**（`h-[clamp(13rem,37vh,23rem)]`、`w-[min(80vw,1000px)]`），车图贴盒子下沿 |
| 车的位置 | 居中于「标题底边 → 车名顶边」之间的**剩余空间**（`.hero-stage-layer` 是 `flex-1` 正常流元素） |
| 归一方式 | **按面积**：所有车占据相同面积，长宽比只决定它是宽而扁还是高而窄 |
| 倒影 | 车台下方溢出，不参与居中计算 |
| 车名 | Oswald 大写，如 `MANHART MH4 GTR II`（去掉 `(992)` 这类底盘代号后缀） |
| 参数、按钮 | 保持中文 |

**为什么车台必须写死尺寸**：原来车图是「宽度定死 + `h-auto`」，车越高整块越高，
换车时页面高度跳动。盒子恒定后轮胎着地线固定，倒影与地面阴影才有稳定基准 —— 这是产品图册的做法。

**为什么是「剩余空间居中」而不是「视口正中」**：视口正中 ≠ 视觉居中。
上方是两行超大标题（视觉重量大），下方只有一行车名，按视口居中时车读起来仍然偏高。

**为什么按面积而不是按高度归一**（2026-10-16 修订）：盒子高度写死意味着「按高度归一」，
于是车的面积完全被长宽比决定。改判时那批素材长宽比 1.56–2.33，同样的车台高度下
面积差 **1.48 倍** —— 最瘦的那台看起来就是小一号，这是 Minus 报的问题。

改为 `h = sqrt(A / r)`，`A = 车台面积 × 0.5`，长宽比只决定形状不决定大小：

| 视口高 | 车台 | 按高度归一极差 | 按面积归一极差 |
|---|---|---|---|
| 1080 | 1000×368 | 1.48× | 1.00× |
| 900 | 1000×333 | 1.48× | 1.00× |
| 800 | 1000×296 | 1.48× | 1.08× |

`h` 超过车台高度时按高度等比封顶（保持形状，不拉扁）。取 0.5 与 37vh 这组值的依据是
**按当时那批素材**让最瘦的 1.56 在 900px 高视口下刚好不触顶（需要 327px，车台 333px）。

> 换成现在这批（2026-10-16）之后，触顶阈值是 `r > 1.50`，而现在的素材是
> 汽车 1.85–2.53 / 摩托 1.14–1.71 —— **摩托会触顶，面积小一截**。
> 首屏那四台换血后的实测：M4 Vorsteiner 166318 / MX-5 166144 / CFMOTO 675SR 152514 /
> CBR1000RR-R 126540 px²。两台汽车极差 1.001×；两台摩托都是触顶的降级
> （675SR 92%、火刃 76%）。这是有意的，不是 bug：图片必须保持形状。
> 想让四台严格相等就把 `STAGE_FILL` 降到 0.45 以下（阈值变 `r < 1.35`），代价是所有车一起小 5%。
> 顺带一提，首批那四台（Manhart / S 1000 RR / GT 63 S / CFMoto）里三台汽车极差只有 1.002×，
> 但它们在 2026-10-16 因抠图不干净整批落选 —— **面积均等是次要指标，够干净才配上首屏**。

公式与常量在 `src/lib/fit.ts`（`fitByArea` / `STAGE_FILL`），
`scripts/cutout-cars.py --check` 的渲染尺寸预估读同一套常量。

### 3.6 素材规格（2026-10-16 新增）

素材可整体替换，动效与设计语言不依赖具体图。Minus 自选图时按下表来。

**去哪选**

不要找「已经是透明 PNG」的图 —— 那类站基本都禁商用（pngimg 是 CC BY-NC 4.0，
Wikimedia 上多数透明车图也是 NC）。正确做法是**找一张干净的实景照，抠图交给流水线**：
授权干净，尺寸也可控。

| 来源 | 授权 | 备注 |
|---|---|---|
| Unsplash / Pexels | 免费商用，署名非必需 | 最省事，首选 |
| Wikimedia Commons | 逐张看（CC0 / CC BY / CC BY-SA） | CC BY 系列需署名 |
| pngimg 等透明 PNG 站 | **CC BY-NC 4.0，禁商用** | 不要用 |

**放哪**

`public/cars/` 下，命名 `品牌-车型.jpg`（kebab-case，与 mock 里的 `cutout` 字段对应），
然后跑抠图流水线生成 `public/cars/cut/*.webp`。新增车辆要在 `src/api/mock.ts` 里加条目。

**分辨率**

源图**长边 ≥ 2500px**。理由：抠图产物长边封顶 1600px，首屏（车高 ≤ 368 CSS px）用不完，
但详情页大图在 DPR2 下要 **2880 设备像素** —— 现有 1600px 不够。

> **补充（2026-10-16，M2 实施后）**：这条的**触发条件收窄了**，别照字面执行。
> 详情页 hero 走的是**原图**（`object-cover`，3000–7680px），不是抠图 —— 抠图是给首页
> 「车在白色影棚里」那套构图用的，详情页要的是真实环境照。所以 **M2 没有也不需要**
> 把 `--max-width` 提到 2800 重跑流水线。
> 只有将来详情页改成也用抠图（例如做多角度旋转或大片留白的展示版式）时，才需要动它。

**选图标准**（直接决定抠图质量，比分辨率更重要）

- 正侧或轻微 3/4 前侧；不要俯视/仰视
- **整车完整入画、四周留白** —— 贴边的车抠出来会被切掉
- 背景干净（纯色墙 / 空地 / 天空）
- 光照均匀；地面投影不要重
- 画面里不要有人、第二台车、地面倒影 —— 最大连通域会选错主体

**筛图工具**

`scripts/cutout-cars.py --check` 读候选图，按最差优先列出：是否贴边（会被切）、
背景有几个连通域（可能选错主体）、主体长宽比、半透明像素占比、主体占画面比、
以及**按 §3.5 公式预估的首屏渲染尺寸**。有问题的直接换图，别等抠完再看。

`--check` 是筛子不是判官 —— 它筛不出的失败模式（背景结构物与车身连成一片、
车轮被平切、底部混进背景杂带）和补足它的两条人工检查，写在 §3.7。

```bash
.cutout-venv/bin/python scripts/cutout-cars.py --check --src public/cars
.cutout-venv/bin/python scripts/cutout-cars.py --check ~/Downloads/*.jpg --preview /tmp/cut
```

**摩托车（2026-10-16 已实施）**

摩托车与汽车**混排**，不拆表：同一张 `tb_shop`、同一套接口、同一个列表，
靠 `Car.kind: 'car' | 'motorcycle'`（缺省 `'car'`）区分。拆表要想清楚代价 ——
后端 schema、全部查询、缓存 key、GEO 周边都要分叉，而「摩托也是车，只是少两个轮子」
在数据模型上是成立的。

- 判断缺省口径只有一处：`car.ts` 的 `kindOf()`，调用点不许自己写 `?? 'car'`
- 品牌导航上方一行「全部 / 汽车 / 摩托」（`KindTabs.vue`）。切到某个大类时，
  **该大类一台车都没有的品牌整块撤掉** —— 点进去是空列表，留着是骗点击
- 摩托不写 `gearbox`：`'自动' | '手动'` 是汽车的分类法，摩托是国际挡序列变速箱，
  硬塞进这两档是错的数据。改用 `displacement`（`999cc` 而不是 `3.0T`）区分

摩托车选图额外要求：正侧面、整车含前后轮完整入画、不要骑手。

**摩托普遍比汽车高瘦**（当前池子：汽车 1.85–2.53，摩托 1.14–1.71），
于是摩托更容易触到 §3.5 的高度封顶、面积小一截。若摩托要上首屏，
选**长宽比 ≥ 1.5** 的（接近正侧、不要 3/4 俯角）—— 那是唯一能避开封顶的办法，
而且正侧面本来也是这套视觉想要的机位。

### 3.7 首屏选车口径（2026-10-16 定稿）

首屏四台是**编辑精选**（`car.ts` 的 `HERO_CAR_IDS`），不是数据切片 —— 首屏是
「车居中立在舞台上」的构图，对素材的要求比列表卡片高一个量级。

**入选口径只有一条：抠图干净。**

> 2026-10-16 修订：原口径里的第 2 条「四台车头朝向一致（都朝右）」**已由 Minus 撤销**
> （「我也不要求车头一致了」）。撤销的理由站得住：同向排列带不来多少整齐感，
> 却把可选池砍掉一大半，逼着人在「构图整齐」和「抠图干净」之间二选一 ——
> 而抠图一旦脏，是整个画面塌掉，不是美观减分。
> 现在四台实际落成「左-右-左-右」交替，读起来反而有节奏。

**第 1 条「尽量黑色」也随之降级**：四台里三台是黑的（M4 Vorsteiner / MX-5 / CFMOTO 675SR），
第四台本田火刃是红蓝白花的 —— 不是选择，是池子里干净的摩托抠图只有两张（另一张就是 CFMOTO），
没有替换余地。想要第四台也素净，得先补一张干净的摩托侧身照。

**怎么判「干净」是可复现的**，不许靠印象（血泪教训：`--check` 的连通域指标查不出轮子被吃掉，
缩略图也看不出朝向）。两条：

1. **几何体检**：轮廓最后几行的宽度必须**单调收窄到接近 0**。车停在地上时轮胎最低点是一个
   切点；若最后一行还很宽然后骤停，说明轮廓被一条水平线切断 —— 就是「少轮子」。
   同理看连通域数量（游离碎片，AMG GT Black Series 的后轮就是这么掉的）与次块占比。
2. **合成到深底上目检**。白底会把混进来的浅色地面、阴影藏在白色里；深底让任何非车身像素
   现形。GSX250R 的底部有一条 1053px 宽的草地带，白底完全看不出，深底一目了然。

> 注意 `crop(getbbox())` 意味着**每张抠图产物的 alpha 都必然贴满四边**，

### 技术栈修正记录（M1 实施时发现）

原计划写的是 `motion`（原 Framer Motion）+ shadcn-vue + Inspira UI，实施时修正为：

1. **`motion` 14.x 已移除 Vue 支持。** 装完后 `node_modules/motion` 里没有任何 vue 产物，
   `package.json` 的 exports 只有 `.` / `/react` / `/three`；Vue 版已拆成独立包 `motion-v`。
   不再引入它的真实理由是：**没必要**。GSAP 3.13 起被 Webflow 收购后全部插件开源免费，
   `Flip` 正好是共享元素转场、`SplitText` 正好是逐字入场，能力完全覆盖，
   且与 Lenis 共用同一个 ticker。两套动画引擎并存只会互相抢 rAF 帧。
2. **shadcn-vue / Inspira UI 暂未引入。** M1 的组件（按钮 / 标签 / 骨架屏 / 卡片）
   手写成本低于配置 CLI 与主题桥接的成本。它们的价值在复杂交互组件，
   等真正需要（弹窗、下拉、日期选择）再按需拷贝。
3. **TypeScript 锁在 5.9.3。** `vue-tsc@3.3.13` 的 peerDependencies 写的是
   `typescript: ">=5.0.0"`，但代码里仍 `require('typescript/lib/tsc')` ——
   TS 7（Go 重写版）已不再导出该子路径，于是装 TS 7 会直接崩。
   这是 vue-tsc 声明与实现不一致，不是配置问题。

### 关于组件库的说明

用户参考的 cult-ui / Aceternity / Magic UI **均为 React-only，无 Vue 移植**。
但这类库本质是 copy-paste 的代码集合（shadcn 模式），组件里真正有价值的部分

因此策略是：

1. **按需拷** —— shadcn-vue + Inspira UI，只在需要复杂交互组件时引入（M1 的简单组件手写更省）
2. **对着抄** —— 上面三个 React 库里的组件，照设计用 Vue + Tailwind + GSAP 重写

### 5.2 前端必须处理的后端特性

1. **token 注入**：header 名是**小写** `authorization`，axios 拦截器统一加；401 统一跳登录
2. **附近车商**：需要浏览器定位（`navigator.geolocation`）才有 GEO 排序，不给坐标是普通分页
   —— **两套渲染逻辑**
3. **Feed 流分页不是普通分页**：用 `lastId + offset` 滚动加载，与 `current` 页码完全不同
4. **秒杀返回 ≠ 已落库**：接口返回订单 id 时订单还在 Redis Stream 排队，不能立刻查订单表
5. **列表接口不返回 `total`**（2026-10-16 M3 补充）：`/shop/of/type` 与 `/blog/hot` 都走
   `Result.ok(list)` 单参重载，`total` 恒为 `null`。所以「还有没有下一页」只能按
   **满页判据**（`list.length === PAGE_SIZE`）推。代价是最后一批恰好凑满时多一次空请求 ——
   这是没有 total 时无法避免的，界面上表现为「点一下没反应」，不是 bug。
6. **后端形状必须过适配层**（2026-10-16 M3 补充）：`Shop.images` / `Blog.images` 都是
   **逗号串**（MySQL 没有数组类型），`avgPrice` 单位是**分**，`Blog` 的作者是**平铺**的
   `userId`/`name`/`icon` 而不是嵌套对象。
   **字段映射只允许发生在 `src/api/adapt.ts`**；在组件里就地打补丁等于把这一层架空，
   漏一处就是详情页白屏或整块 section 消失。

   > 第 6 条是**踩过坑才写进来的**：`fetchHotReviews` 的真机分支原先直接把平铺的 `Blog`
   > 当 `Review` 返回，`ReviewFeed` 读 `undefined.nickName` 抛 TypeError，
   > 首页口碑区**整块从 DOM 消失**，而控制台只有一条不显眼的错误。
   > M1 时期没暴露，因为 `USE_MOCK` 默认开着，而 mock 数据本来就是 `Review` 形状。

### 5.3 401 的实际形状（2026-10-16 M3 订正）

本节原先（第 1 条）写的是「401 统一跳登录」，但没说**后端到底返回什么**。实测订正：

- 未登录访问受保护接口，后端返回的是**裸 HTTP 401 + 空 body**（`LoginInterceptor` 直接
  `response.setStatus(401)`），**不是** `{"errorMsg":"请登录"}`。
  所以 `client.ts` 里判 `errorMsg === '请登录'` 那条分支是**防御性的**，不是主路径 ——
  主路径是 401 状态码。全仓库 grep `请登录` 在 Java 侧只有一处，在一段注释里
  （`config/MvcConfig.java`），没有任何 Java 代码会返回它。
- `POST /user/login` 成功后返回的是**裸 token 字符串**（不是 JSON 对象），
  拿到 token 后必须再调 `GET /user/me` 才得到 `{id, nickName, icon}`。
- **`POST /user/logout` 是后端唯一的占位接口**（返回 `功能未完成`）。所以「登出」只能前端做：
  清 token + 回首页，**不能调后端**。

- **Lenis 平滑滚动** —— 全局惯性

> **修订（2026-10-16，M2 实施）**：本节原来写「详情页随滚动切换『外观 → 内饰 → 参数 → 车况』」。

> 主体图**的前提下根本不存在 —— 没有第二张图可渐变。

骨架屏 / 交错入场（stagger）/ hover 微交互 / 状态过渡。不做滚动叙事。

### 6.3 性能与降级

- 只动 `transform` 和 `opacity`
- `will-change` 克制使用

### 6.4 开场与转场（2026-10-16 新增）

**开场幕布**（白幕溶解，2026-10-16 由黑幕开合改写）

全屏白 → AXLE 字标逐字浮现 → 幕布整体淡出，首屏从底下交叉溶解进来。

| 时刻 | 动作 |
|---|---|
| 0.20s | 字标逐字浮现：`opacity 0→1` 且 `y 26→0`（0.9s，`expo.out`，stagger 0.06） |
| 1.28s | 字标就位，停一拍让观众读到 |
| 1.50s | 幕布 `opacity → 0`（1.1s，`power2.inOut`），字标同时继续上浮并淡出 |
| 1.72s | **放行首屏**（`HANDOFF = 0.2`） |
| ~2.60s | 幕布淡尽，`lenis.start()`，卸载自己 |

**为什么是白幕而不是黑幕**：全站纯白底，一块全屏黑幕在白站上读起来像加载失败的故障态，
而且黑→白的跳变本身就很吵。改白幕之后幕布与页面同色，「揭幕」从「抽走一块板子」
变成「溶解」，这才是要的效果。代价是幕布本身看不见了（白盖白），观众能读到的只有
**字标**与**首屏的浮现**两件事，所以字标必须留够时间，交接点必须压进淡出过程里。

**交接点为什么压在淡出前段（0.2）而不是中后段**：幕布白、页面也白，淡出的前段什么都看不见。
字标化掉之后、首屏起手之前会留一段空白，读起来像「加载完了但页面是空的」。
压在 0.2，首屏就在幕布还有约八成不透明度时开始淡入 —— 白幕当一层纱，两边同时变，
这才叫交叉溶解。太早（幕布还实着）首屏等于白演一遍；太晚（=100%）中间必然空一拍。

⚠️ **幕布淡出不能用 `visibility` / `display` 收尾**，那样最后一帧会硬切。靠 `opacity` 走到 0，
再由 `App.vue` 卸载组件，中间不留跳变。

三条约束：

1. **每次完整文档加载都放，不分路由、不看是否本会话第一次。** 理由是「开场是进入体验的门」，
   而「进入」= 一次完整文档加载。站内 SPA 导航根本不重新执行 `index.html` 里的那段脚本，
   所以天然不会放 —— 不需要 `sessionStorage` 帮忙去记。
   上一版用 `sessionStorage` 记「已放过」，副作用是**刷新也不再放**，而刷新恰恰是最常见的
   「重新进入」，等于把门焊死了。`?nointro` 给开发留一个不依赖系统设置的跳过开关。
2. **防首帧闪底色必须内联。** 判断写在 `index.html` 的 `<head>` 内联脚本里
   （满足条件就给 `<html>` 加 `intro-boot`，并由内联 `<style>` 把底色刷成幕布色）。
   `main.css` 随 JS bundle 加载，等它到已经闪了一帧。`src/lib/intro.ts` 只读这个 class，
   判断逻辑**只有一份**。内联脚本还挂了一条 6s 兜底定时器撤掉它：bundle 加载失败时没人来撤。
   正常路径下幕布挂载时（约 2.2s）已经撤过，兜底是空操作。
   内联脚本必须排在字体 `<link>` **之前** —— 浏览器会阻塞普通 `<script>` 直到前面的样式表就绪，
   字体 CDN 慢的时候这段判断会跟着被推迟。
3. **幕布期间 `lenis.stop()`**，淡出时 `lenis.start()`，否则能透过幕布滚页面。
   组件 `onUnmounted` 里再 `start()` 一次 —— 时序被打断（快速刷新）时别把滚动锁死。

**路由转场**

- `SiteLayout` 上提到 `App.vue`，包住 `<RouterView>`。原先它被每个 view 各包一层，
  换路由时整站（含 header/footer）都在重建 —— 这是「切换突兀」的根因。
- `<Transition name="route" mode="out-in">`，key 用 `route.path`。
  enter 0.5s 淡入 + `translateY(12px)`（`--ease-cinematic`），leave 0.3s 收得快。
- **`<main>` 必须 `min-h-[100svh]`**：`out-in` 期间旧内容先卸载，main 高度塌到 0
  会让 footer 瞬间跳到页首。布局根节点的 `min-h-screen` 拦不住这一幕。
- 切路由后要**显式驱动 Lenis 归零**（`lenis.scrollTo(0, { immediate: true })`）。
  router 的 `scrollBehavior` 走 `window.scrollTo`，Lenis 的内部 `targetScroll`
  不会跟着变，下一帧会被拉回去。所以 `scrollBehavior` 是**删掉**而不是改写的
  —— 两套机制同时存在必然打架。代价是浏览器前进/后退不再恢复滚动位置（统一回顶部），
  M2 若要恢复位置，得在 Lenis 侧实现，不要再把 `scrollBehavior` 加回来。
- 归零挂在 `<Transition>` 的 `@after-leave` 上，不是路由 watcher：
  `out-in` 的离开动画有 0.3s，在离开期间滚到顶会被看见（旧页一边淡出一边往上跳）。
- **共享元素转场改手写 FLIP**（2026-10-16，M2 实施时定）。原计划用 GSAP Flip 插件，放弃了：
  `mode="out-in"` 的转场下**卡片在详情页挂载之前就已经被卸载**，`Flip.getState()` 拿到的元素
  已不在文档里，能不能用取决于 GSAP 的未文档化行为 —— 不值得赌。而这段数学本身只有四个数
  （`x/y` 位移 + `scaleX/scaleY`），抽成 `src/lib/flip.ts` 的纯函数还能单测。
  记录方式是一张**模块级的一次性矩形**：卡片 `@click` 时 `recordFlipSource()`，
  hero 挂载时 `consumeFlipSource(id)` —— id 不匹配就丢弃，这一条同时承担了
  「这段矩形确实属于正在显示的车」的校验（刷新 / 直连 / 前进后退都因此自然跳过）。
- **hero 的图区是 4:3 两栏构图，不是全宽大图**（2026-10-16）。这是对原计划的**有意偏离**，
  理由是转场的正确性：卡片图是 4:3，全宽 hero 在 1440×480 时是 3:1，把卡片矩形非等比放大过去
  `scaleX`（≈0.28）与 `scaleY`（≈0.67）差 **2.4 倍**，飞行途中图会被横向压扁 —— 那是故障不是速度感
  （「靠 0.8s 高速运动盖过去」对 1.2 倍以内成立，对 2.4 倍不成立）。
  把图区也做成 4:3，两个 scale 完全相等，**连裁切内容都一致**（同源图 + `object-cover` + 同比例），
  于是转场是真的无缝，而不只是够快。代价是首屏不再是满幅照片，换来价格 / 车名 / 车况在第一屏就读得到
  —— 详情页本来就该这样。
- 转场 CSS 放全局 `main.css`：`<Transition name="route">` 由 `App.vue` 直接渲染，
  没有 scoped 宿主，写进任何组件的 `<style scoped>` 都匹配不到。

### 7.1 表结构（实际加列）

`tb_shop` 实际加了 **8** 个列（原方案列 6 个）：

| 列 | 类型 | 说明 |
|---|---|---|
| `mileage` | `DECIMAL(6,1)` | 里程（万公里） |
| `register_date` | `VARCHAR(7)` | 上牌时间 `YYYY-MM` |
| `gearbox` | `VARCHAR(8)` | 自动/手动，摩托车为 `NULL` |
| `fuel` | `VARCHAR(16)` | 汽油/纯电/混动 |
| `displacement` | `VARCHAR(16)` | 排量，如 `3.0T` / `999cc`；纯电为 `NULL` |
| `owner_count` | `TINYINT` | 过户次数 |
| `kind` | `VARCHAR(16)` | `car` / `motorcycle`，默认 `car` |
| `original_price` | `BIGINT UNSIGNED` | 新车指导价，**单位：分** |

`tb_shop_type` 加 `mark VARCHAR(8)`（拉丁字标，如 `BMW`）。

> **为什么多出 `kind` 和 `original_price` 两列**：`kind` 是承重件 —— 首页大类 tab 与列表筛选
> 全由它驱动，没有这一列真机路径只能是纯汽车，那两个 tab 就是死的（点了没反应，
> 且不会报错）。`original_price` 是详情页「新车指导价」那一行的来源，前端 mock 里本来就有这个字段。
>
> **`mark` 为什么不复用 `name`**：`mark` 在界面上走 `--font-display`（Oswald），
> 而 **Oswald 没有 CJK 字形** —— 中文名落进去会掉回另一种字体，一行里两种字体比少一行更难看。
> 加一个可空列，比在适配层里硬编码一张「中文→拉丁」映射表干净。

### 7.2 数据映射与三条约定

| hmdp | 二手车 |
|---|---|
| `tb_shop` | 车源（一辆车 = 一条记录） |
| `tb_shop_type` | 品牌 |
| `tb_voucher` | 购车券（定金抵扣、保养券、延保券） |
| 秒杀券 | **限时特价车** |
| `tb_blog` | 提车作业 / 用车口碑 / 验车报告（**内容尚未改造，见下**） |
| `tb_follow` | 关注车商 / 车评人 |

三条**实测口径**，改数据前必须知道：

1. **`images` 写的是前端相对路径**（`/cars/bmw-m4-vorsteiner.jpg`），不是 nginx 绝对 URL。
   这些图在**前端仓库**的 `public/cars/` 下，相对路径直接命中前端 origin，不依赖 nginx。
   多个路径逗号分隔（后端那一列是 `varchar(1024)`，逗号串是 MySQL 没有数组类型的妥协）。
2. **`avg_price` 保持 hmdp 原语义：单位是「分」**，不改成元。改单位会静默破坏后端契约
   （`tb_voucher.pay_value` 同理），换算由前端 `adapt.ts` 的 `fenToYuan()` 负责。
3. **`cutout`（首屏抠图）没有对应列，也不该有** —— 那是前端仓库 `public/cars/cut/` 的目录布局，
   后端不知道也不需要知道。由 `adapt.ts` 的 `cutoutPathOf()` 按**命名约定**推导
   （`/cars/x.jpg` → `/cars/cut/x.webp`），并且只有白名单内的车才给（见 §3.7）。

### 7.3 数据准备（实际结果）

- **`tb_shop` id 1–14** 全部改写成车源，**id 与前端 mock 的车 id 一一对应**
  （`mockCars` 的 id 是 1–13）。于是 `/car/5`、`/seckill/5` 在 mock 与真机上**指向同一台车** ——
  验收就是「同一页、两种数据源」。
- **真机 14 台 vs mock 13 台**：`tb_shop` 本来就有 14 行，不删就只能填满。
  第 14 台（`BMW M 1000 RR`）用的是 mock 里没用到的另一张真实照片。
  验收脚本就靠这个差值确认「两种数据源不是同一批数据」。
- **`tb_shop_type` 10 行全部复用为品牌**：其中 8 个与 mock 的品牌对齐，
  多出的 id 9/10 被复用成**保时捷 / 沃尔沃** —— 它们**没有车源**，
  前端品牌导航点进去是空态列表（不是 bug，是「不删行」这条约束的代价）。
- **券**：`tb_voucher` 新增 4 张车源券（秒杀 101/102 挂车 5，103 挂车 12，104 挂车 10），
  `tb_seckill_voucher` 4 行，库存与时间窗由 `scripts/init-seckill-stock.sh` 灌进 Redis。
- **GEO**：每台车都填了坐标，`scripts/init-redis-geo.sh` 重灌 `shop:geo:{typeId}`。
  坐标**刻意集中在 3 个城市**（2026-10-16 调整）：

  | 城市 | 台数 | id | 站在城市中心实测（`/shop/of/type` 带 `x/y`） |
  |---|---|---|---|
  | 上海 | 5 | 1 / 2 / 3 / 7 / 9 | 人民广场 → 5 台，0–3.3 km |
  | 北京 | 5 | 6 / 11 / 12 / 13 / 14 | 国贸 → 5 台，0.5–2.6 km |
  | 深圳 | 4 | 4 / 5 / 8 / 10 | 南山科技园 → 4 台，0–1.7 km |

  **为什么必须集中**：半径是后端**硬编码**的 5 km（`ShopServiceImpl.java` 的
  `new Distance(5000)`，没有参数可调）。调整前 14 台散在 8 个城市（上海/北京/杭州/深圳/
  成都/广州/南京/济南），多数城市只有 1 台 —— 「附近优先」在任何城市都只能查出 1 台，
  看着像坏了。集中后同城 4–5 台互相都在半径内，这个开关才演示得出来。
  **代价**：这 3 城之外的定位查出来就是空的（杭州实测 `[]`），列表页为此有空态文案，
  且**不静默退回全部车源**。

  坐标存在**两处**且必须同步：真机 `usedcar.sql` 的 `tb_shop.x/y`（连同 `address`）、
  mock 侧 `mock.ts` 的 `mockCarCoords`（连同 `mockCars[].address`）。两处一致时
  「同一个定位 → 同一批车」在两种数据源下逐台对应，E2E 拿这条当判据
  （深圳定位恰好 4 台，mock 与真机都验）。
- **Redis 侧共三个初始化脚本**，都放在 `hmdp-master/scripts/`：GEO、秒杀库存、
  **商铺详情缓存（`init-shop-cache.sh`）**。第三个是 2026-10-16 踩坑之后确认必需的 ——
  见下面那条 ⚠️。

> ### ⚠️ 详情接口走「逻辑过期」缓存：冷缓存 = 店铺不存在
>
> `ShopServiceImpl.queryById` 用的是 `CacheClient.queryWithLogicalExpire`，
> 它的语义是**缓存没命中就 `return null`，不回查数据库**（假设缓存已被预热）。
> 于是 `GET /shop/{id}` 会回 `{"success":false,"errorMsg":"店铺不存在"}` ——
> 车明明在 MySQL 里。
>
> 症状极具误导性：`/shop/of/type`（列表）**照常能列出它**，所以是
> **列表正常、详情页全挂**，很容易被当成前端路由或适配层的问题。
>
> 2026-10-16 实测踩到：改坐标时按旧步骤跑 `redis-cli keys 'cache:shop*' | xargs redis-cli del`，
> 14 台车的详情立刻全部变成「店铺不存在」。修法是**重灌** `./scripts/init-shop-cache.sh`
> （它自己就是「先清空再重建」，所以不该再单独 `del` 一次 —— 旧步骤把这句放在最后，
> 顺序本身就是错的）。
>
> 预热一次即可：值的 `expireTime` 到点后，下一次读会拿互斥锁异步回源重建，之后自维持。
> **Redis 被 flush 或重启后需要重跑。**

> ### ⚠️ 已知缺口：`tb_blog` 没改，真机首页口碑区是餐厅内容
>
> 实测（2026-10-16）：`tb_blog` 仍是 **4 行 hmdp 原始数据**，内容是餐厅探店
> （「无尽浪漫的夜晚丨在花丛中摇晃着红酒杯品战斧牛排」这类），作者是 `可可今天不吃肉`，
> 图片指向 `/imgs/blogs/...` —— **本前端仓库没有这批文件，4 张全部 404**。
>
> 后果：真机模式下首页口碑区渲染出来、不报错，但**图文都对不上二手车这个主题**。
> 把这批内容和图换成车的，属于**数据迁移**（要改 `tb_blog` + 准备图片），**M3 未做，留给 M4**。
>
> 顺带记两条**踩过的坑**（都在 M3 收尾时发现并修掉）：
>
> ① `fetchHotReviews` 原先不过适配层，平铺的 `Blog` 被当 `Review` 用，
> `ReviewFeed` 读 `undefined.nickName` 抛 TypeError，**首页口碑区整块从 DOM 消失**
> （详见 §5.2 第 6 条）。
>
> ② 真机 `content` 是 HTML 片段（实测只有 `<br/>`，40 + 29 个），而 mock 全是纯文本 ——
> 不过适配层时用户看到的是**字面的 `<br/>`**。已由 `blogToReview()` 把换行标签归一成空格。
> 注意它**不是 sanitizer**：别的标签原样留着，M4 要渲染富文本应该去用原始的 `BlogDTO`。
>
> 现在 E2E 里有两条守着：「首页没有未捕获的渲染错误」与「口碑区正文没有把 HTML 标签当字面文本显示」。
