- 日期：2026-10-15
- 状态：待 Minus review
- 关联仓库：`本地生活点评平台`（init 后端）、`hmdp-master`（完整版后端，分支 `usedcar`）

---

## 1. 背景与目标

hmdp 是跟着黑马 Redis 教程做的实战项目，后端已实现：手机号验证码登录、Redis token 滑动续期、
商户缓存三件套、Redis GEO 附近商铺、优惠券秒杀（Lua 原子扣减 + 一人一单 + Stream 异步削峰）、
探店笔记、点赞、关注与 Feed 流、签到。

**本项目要做的事**：用 Vue3 重写前端，把主题从「本地生活点评」改造成「二手车交易平台」，
做出**作品集级、电影级动效**的 PC 端前端。

**为什么是二手车**：`一辆车只能卖给一个人` —— 秒杀 + 一人一单的语义在这里完全自洽，
不需要像卖商品那样硬凑「限量 N 件」。这是所有候选主题里贴合度最高的。

**技术内核不变**：缓存、分布式锁、原子 Lua、异步削峰、LBS、Feed 推拉 —— 原有技术亮点全部保留。

## 3. 视觉系统

### 3.1 零彩色 UI（核心约束）

```
色板   纯中性灰阶，不带色相（no blue-tint / no warm-tint）
       #FFFFFF → #0A0A0A

强调   不用色相，用明度反转
       主按钮 = 纯黑底 + 白字
       次级按钮 = 透明底 + 细描边

唯一色彩来源 = 车辆照片本身
       界面零饱和度 → 车漆颜色成为页面上唯一跳出来的东西
```

**状态反馈同样不用颜色**：

- 抢购成功 → 白光从中心爆开
- 抢购失败 → 界面瞬间压暗 + 轻微震动

纯明度语言。不用绿/红。

### 3.2 统一亮色基调（2026-10-15 修订，替代原「混合基调」）

全站统一 `#FFFFFF` 底，不分暗区亮区。

原方案是「营销页暗色做电影感 / 功能区亮色保可用性」。**推翻的理由**：车是抠图资产，
本身没有场景。放在纯黑上时，界面必须补三层空间感（顶光、地平线、暗角）才不让车飘起来，
那三层是界面在替照片演戏；放在白底上，车直接成立，界面可以退到只剩排版。

动效力度仍然分档（见 §6），但那是节奏差异，不再是明暗差异。

| | 旗舰页 | 功能页 |
|---|---|---|
| 页面 | 首页 / 车辆详情 / 抢购页 | 其余 |
| 底色 | `#FFFFFF` | `#FFFFFF` |
| 动效力度 | 电影级 | 精致克制 |
| 内容 | 大图叙事 | 密集信息 |

### 3.3 车是主体

车辆图片永远占据视觉重心，UI 元素退成背景。
列表卡片图占大头，详情页满屏大图，任何装饰不允许抢戏。

### 3.4 字体

- 中文：思源黑体 / Noto Sans CJK（本机字体，不引 webfont）
- 正文与数字：Inter —— 价格、里程、车牌的数字质感是重点
- **展示体：Oswald**（2026-10-15 修订新增）

字体规则：`--font-display` **只用于全大写的拉丁展示文字** ——
AXLE 字标、首屏主标题、首屏车名、品牌 mark、段落 eyebrow。
Oswald 没有 CJK 字形，中文一旦落进来会掉回 Noto，所以混排的中文标题一律不用它。

首屏主标题与车名改用英文，就是为了让这套展示体成立（见 §3.5）。

### 3.5 首屏规格（2026-10-15 修订）

参照物：Minus 给的示例图（`THE MORNING` 那张）—— 全大写、超大字号、紧凑无衬线标题，
配一枚极小、字距拉开的顶部小标签，车居中大图。

| 项 | 规格 |
|---|---|
| 底色 | `#FFFFFF`，底部过渡到 `ink-100` 暗示地面 |
| eyebrow | `AXLE · 严选二手性能车`，11px，`tracking-[0.34em]`，中文 |
| 主标题 | `EVERY CAR DESERVES A SECOND START`，Oswald，`clamp(2.4rem,6.6vw,5.5rem)`，`leading-[0.92]`，大写 |
| 车台 | **尺寸写死**（`h-[clamp(15rem,42vh,26rem)]`），车图盒内 `object-contain` |
| 车的位置 | 钉在视口正中（绝对定位居中层），与上下文案体量无关 |
| 倒影 | 车台下方溢出，不参与居中计算 |
| 车名 | Oswald 大写，如 `AUDI RS6 AVANT` |
| 参数、按钮 | 保持中文 |

**为什么车台必须写死尺寸**：原来车图是「宽度定死 + `h-auto`」，车越高整块越高，
换车时页面高度跳动。盒子恒定后所有车按**高度**归一，轮胎着地线固定，
倒影与地面阴影才有稳定基准 —— 这是产品图册的做法。

## 4. 技术栈

```
构建      Vite + TypeScript 5.9
框架      Vue 3.5（Composition API + <script setup>）
状态      Pinia
路由      Vue Router
样式      Tailwind CSS v4（@theme 定义设计 token，无 config 文件）
动效      GSAP 3.15 全插件：ScrollTrigger / Flip / SplitText
平滑滚动  Lenis（全局单例，与 GSAP ticker 同步）
HTTP      axios（拦截器统一注入 token）
测试      Vitest + jsdom
验收      puppeteer-core 驱动系统 Chrome，脚本截图人工 review
```

### 技术栈修正记录（M1 实施时发现）

原计划写的是 `motion`（原 Framer Motion）+ shadcn-vue + Inspira UI，实施时修正为：

1. **`motion` 14.x 已移除 Vue 支持。** 装完后 `node_modules/motion` 里没有任何 vue 产物，
   `package.json` 的 exports 只有 `.` / `/react` / `/three`；Vue 版已拆成独立包 `motion-v`。
   不再引入它的真实理由是：**没必要**。GSAP 3.13 起被 Webflow 收购后全部插件开源免费，
   `Flip` 正好是共享元素转场、`SplitText` 正好是逐字入场，能力完全覆盖，
   且与 Lenis 共用同一个 ticker。两套动画引擎并存只会互相抢 rAF 帧。
2. **shadcn-vue / Inspira UI 暂未引入。** M1 的组件（按钮 / 标签 / 骨架屏 / 卡片）
   手写成本低于配置 CLI 与主题桥接的成本。它们的价值在复杂交互组件，
   等真正需要（弹窗、下拉、日期选择）再按需拷贝。
3. **TypeScript 锁在 5.9.3。** `vue-tsc@3.3.13` 的 peerDependencies 写的是
   `typescript: ">=5.0.0"`，但代码里仍 `require('typescript/lib/tsc')` ——
   TS 7（Go 重写版）已不再导出该子路径，于是装 TS 7 会直接崩。
   这是 vue-tsc 声明与实现不一致，不是配置问题。

### 关于组件库的说明

用户参考的 cult-ui / Aceternity / Magic UI **均为 React-only，无 Vue 移植**。
但这类库本质是 copy-paste 的代码集合（shadcn 模式），组件里真正有价值的部分
（缓动曲线、渐变配方、光效叠加、入场时序）全是 CSS 与动画逻辑，与框架无关。

因此策略是：

1. **按需拷** —— shadcn-vue + Inspira UI，只在需要复杂交互组件时引入（M1 的简单组件手写更省）
2. **对着抄** —— 上面三个 React 库里的组件，照设计用 Vue + Tailwind + GSAP 重写

## 5. 架构

### 5.1 目录结构

```
hm-dianping/
├── 本地生活点评平台/    init 后端（教程练习，保留不动）
├── hmdp-master/         完整版后端工作区，分支 usedcar ← 前端连这个
└── hmdp-web/            本前端项目
    ├── CLAUDE.md        项目规则（动手前先写）
    ├── docs/specs/      设计文档
    └── src/
        ├── api/         接口层，按后端模块分文件
        ├── assets/      静态资源
        ├── components/  ui/（shadcn-vue 拷贝进来的）+ business/（业务组件）
        ├── composables/  useScrollAnimation / useAuth / useCountUp …
        ├── layouts/     SiteLayout（全站统一，含 header 与 footer）
        ├── router/
        ├── stores/      Pinia
        ├── styles/      Tailwind + 设计 token
        └── views/       12 个页面
```

### 5.2 前端必须处理的四个后端特性

1. **token 注入**：header 名是**小写** `authorization`，axios 拦截器统一加；401 统一跳登录
2. **附近车商**：需要浏览器定位（`navigator.geolocation`）才有 GEO 排序，不给坐标是普通分页
   —— **两套渲染逻辑**
3. **Feed 流分页不是普通分页**：用 `lastId + offset` 滚动加载，与 `current` 页码完全不同
4. **秒杀返回 ≠ 已落库**：接口返回订单 id 时订单还在 Redis Stream 排队，不能立刻查订单表

## 6. 动效规范

### 6.1 电影级手法（仅旗舰页）

- **共享元素转场** —— 列表车辆卡片点开，图片无缝放大成详情页 hero（GSAP Flip，卡片图已埋 `data-flip-id`）
- **数字滚动** —— 价格、里程、马力从 0 滚到目标值
- **滚动叙事** —— 详情页随滚动切换「外观 → 内饰 → 参数 → 车况」
- **光标跟随 / 光效** —— 克制使用（全站亮色后不再靠光效造气氛）
- **Lenis 平滑滚动** —— 全局惯性

### 6.2 功能页（克制）

骨架屏 / 交错入场（stagger）/ hover 微交互 / 状态过渡。不做滚动叙事。

### 6.3 性能与降级

- 只动 `transform` 和 `opacity`
- `will-change` 克制使用
- 必须处理 `prefers-reduced-motion` 降级
- **Lenis ↔ GSAP 同步是硬性要求**：`lenis.on('scroll', ScrollTrigger.update)`
  + `gsap.ticker.add` + **必须** `gsap.lagSmoothing(0)`，漏了会抖动

## 7. 后端改造（分支 `usedcar`）

**接口路径与响应结构全部不变**，前端照 `hmdp-master/docs/API.md` 写即可。
改造只发生在数据与字段层面。

### 7.1 表结构

`tb_shop` 扩字段（方案已确认）：

```
mileage         里程（万公里）
register_date   上牌时间
gearbox         变速箱（自动/手动）
fuel            能源类型（汽油/纯电/混动）
displacement    排量
owner_count     过户次数
```

### 7.2 数据映射

| hmdp | 二手车 |
|---|---|
| `tb_shop` | 车源（一辆车 = 一条记录） |
| `tb_shop_type` | 品牌 / 能源类型 |
| `tb_voucher` | 购车券（定金抵扣、保养券、延保券） |
| 秒杀券 | **限时特价车** |
| `tb_blog` | 提车作业 / 用车口碑 / 验车报告 |
| `tb_follow` | 关注车商 / 车评人 |

### 7.3 数据准备

- 种子数据：车辆记录（品牌、车型、价格、里程、上牌时间、坐标）
- 图片：Unsplash / Pexels 免费图库，脚本批量拉取 + 统一尺寸处理
- GEO 数据与秒杀库存：沿用 `hmdp-master/scripts/` 下已有的两个初始化脚本

## 8. 风险

| 风险 | 应对 |
|---|---|
| 图片质量决定成败 | 素材是电影感的 90%，先用图库，后续可替换 |
| 滚动动画低端机掉帧 | `prefers-reduced-motion` 降级 + 只动 transform/opacity |
| 12 页全做电影级工作量过大 | 分档：只有 3 个旗舰页做满，其余克制 |
| Lenis 与 GSAP 不同步会抖 | 按标准接法写，写进 composable 统一封装 |
| React 组件库无法直接用 | 走 shadcn-vue / Inspira，缺的对着抄 |
